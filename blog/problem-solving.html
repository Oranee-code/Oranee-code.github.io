Problem Solving

I were blocked on a simple problem:

While I was working on a JavaScript task, and I kept testing my code, but it kept saying it failed!.
I checked everything and couldn’t figure out what was wrong. Everything looked fine to me.

After a long time, I finally found the problem. It was just one missing “s”! Because of that tiny mistake, the whole test failed.

To solve it, I slowly checked each line that helped me find the mistake.

At first, I felt frustrated and confused. But when I finally fixed it, I felt relieved and also kind of proud that I didn’t give up.
What I learned is that in coding, even small things matter—and that patience and double-checking can save a lot of stress!

Solved a problem elegantly.

While I was making my blog, I thought, “Why not make my webpage sparkle?” It would be fun to add a cool effect.

At first, I thought I needed to use only JavaScript, and it would be very challenging and complicated.
After doing a lot of testing and searching, I found out I could use both CSS and JavaScript together.

My JavaScript didn’t work at first, And when it finally worked, it didn’t look the way I wanted. So I had to play around with it a lot.
I used things like setTimeout, a sparkleRemove function, and made other small changes to get it right.

I also played around with the CSS to make the sparkles look nice and move in the right way. It took quite a long time to test and fix everything.
But in the end, I made it work!

I felt happy, and the result looked really cool to me. I learned that coding takes time, and you often need to try different things before it works.
I also learned that combining CSS and JavaScript can make amazing effects if you keep trying.

My sparkle page

Reflect on problem-solving techniques, processes:

  • Pseudocode: I don’t really use this much as I should. I understand what it is, but I forget to do it. I need to useing it more.
  • Trying something: I always try different things to see what works. Sometimes it works, sometimes it doesn’t but I keep trying.
  • Rubber ducky method: I don’t use this much. I don’t really talk to myself or explain the problem out loud.
  • Reading error messages: Sometimes I read them but still don’t understand. If the error is simple, I can fix it. If it’s too long or confusing, I just Google it.
  • Console.logging: I use console.log() a lot! It helps me see what’s happening.
  • Googling: I use Google all the time. I feel very confident. It always helps when I’m stuck or need more explaination.
  • Asking peers for help: I feel a bit shy, especially if I think it’s a small problem. But I know it’s okay to ask.
  • Asking coaches for help: I don’t feel scared to ask them if I needed.
  • Improving with reflection: I’m still learning to do this. I often just move on after fixing a problem, but I know it’s good to stop and think about what I learned.

Ask for help :

I was working on a JavaScript task. When I opened it, I felt very confused. I didn’t ask for help. I just took my time and tried to figure it out by myself.
But it took too long, and I felt like I wasted my time. Next time, instead of doing it all by myself, I should just ask for help so I don’t waste time.
